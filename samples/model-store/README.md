# Model-driven collections

Run the typed model sample with in-memory storage, without an API key:

```sh
go run ./samples/model-store
```

Or use a durable SQLite file:

```sh
go run ./samples/model-store -sqlite /tmp/model-store.db
```

Or start the repository's PostgreSQL instance and use native model storage:

```sh
aspire start --apphost samples/aspire-services/apphost.go
aspire wait postgres --apphost samples/aspire-services/apphost.go
go run ./samples/model-store -dsn 'postgres://postgres:postgres@localhost:54329/vectorstore_test?sslmode=disable'
```

The [shared services guide](../aspire-services/README.md) covers Aspire prerequisites
and stopping the development databases while retaining data.

The sample demonstrates struct tags, generated int64 keys, store-wide embedding
defaults, bounded embedding batches, string-array overlap filtering, text queries,
batch reads and deletes. The default embedding batch size is two texts; change it
with `-embedding-batch-size=128`, or use zero for one request per vector property.
The collection inherits its embedder and batch size from the store.
It deletes the records generated by that run, and retains the collection so it can
be rerun. Its tiny deterministic embedder is an API demonstration, not a semantic
embedding model. For real semantic search, supply a real `vectordata.Embedder`.

See [the model API guide](../../docs/model-api.md) for explicit definitions,
multiple vector fields, native UUID keys, streaming reads and PostgreSQL hybrid
search.
