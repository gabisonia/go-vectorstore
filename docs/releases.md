# Compatibility and releases

`VERSION` selects the source version being prepared or tagged. A version is
available to consumers only after its immutable tag/release is published; consult
[GitHub releases](https://github.com/gabisonia/go-vectorstore/releases). Source on
master may be newer than the latest tag. The [v1.0.0 release](https://github.com/gabisonia/go-vectorstore/releases/tag/v1.0.0)
requires Go 1.26+. Azure AI Search and Pinecone ship as separate modules.
Consult the changelog for changes since the previous tag. See the
[v0.5.0 compatibility review](release-0.5.md) and [upgrade guide](upgrading.md).

## Compatibility policy

### v1.x compatibility

The root module commits to source compatibility across v1 minor and patch
releases. Applications using the original Record API, typed collections,
custom codecs or keyed option literals can update within v1. Third-party
implementations of the published store, collection, codec and search interfaces
continue to satisfy them. New optional operations use separate interfaces and
capability checks. An intentional incompatible change requires a new major version.

The exported additions since v0.7.0 are the single-method
`vectordata.VectorSearcher[T]` interface, Qdrant's `NewNativeVectorSearcher`
and `NewNativeModelSearcher`, SQL Server's `NewNativeModelSearcher`, and
`vectordata/embeddingsearch` with `New`, `Searcher[T]` and `SearchTextIter`.
Existing typed model collections already implement the dense interface.

- **Retrieval.** Preserve projection, key precision, optional-vector behavior,
  distance units and score kinds. Enumeration is lazy. A caller that continues
  after cancellation receives one terminal error matching the context error,
  including after the final hit. Breaking releases resources immediately.
  Documented sentinel and wrapped error types remain matchable with
  `errors.Is` and `errors.As`.
- **Embeddings.** Preserve property, collection and store override precedence,
  explicit vectors, input/output validation and atomic model batch writes.
  The text wrapper embeds once per enumeration using the selected logical
  vector. Runtime generators must be supplied again on reopen.
- **Provider scope.** Portable filters retain their documented NULL semantics.
  Native Qdrant typed search accepts indexed keyword equality and retains server
  tie order. Native SQL Server typed search accepts equality on its mapped text
  field and orders distance ties by key. PostgreSQL ordinary vector search orders
  by distance alone. A search-only adapter grants no collection creation,
  migration or deletion operations. Supported backend versions, operations and
  topologies are listed in the [native support matrix](native-support.md).
- **Persisted data.** Preserve the documented read or explicit migration path for
  supported registrations, values and generated keys. Format changes require a
  version, backup instructions and a migration procedure. The tested paths,
  matching server versions and restore boundaries are in the [upgrade guide](upgrading.md).

Azure AI Search and Pinecone keep independently versioned v0 module contracts.

## Verification and supported versions

Within a supported minor line, patch releases preserve exported APIs, existing
record/model registrations, declared error matching, and supported persisted data.
Fixes can tighten behavior that violates the documented contract, such as yielding
buffered records after cancellation. Applications must not depend on internal SQL,
index names, undocumented error text, timing, or driver implementation details.

CI compares the root module against v1.0.0, Azure AI Search against
`connectors/azuresearch/v0.1.0`, and Pinecone against `connectors/pinecone/v0.1.0`.
Each comparison must report zero incompatible changes. The [upgrade guide](upgrading.md)
records the two package moves that shipped in v0.7.0. Advance each module's
baseline after reviewing its release. Run `git fetch --tags` and
`bash scripts/check-api.sh` to reproduce the comparisons, and
`bash scripts/test-connector-modules.sh` for the independent consumer builds.

The original Record API remains supported alongside model APIs. Current readers
are tested against a committed SQLite database generated by published v0.4.0,
including native values, all vector kinds, required/optional registrations and
generated-key continuation. Keep released fixtures; add new ones when formats
change. This is a backwards-read compatibility check, not a promise that an older
binary understands a newer storage format.

Go/driver/database support changes must be called out. The Go minimum is 1.26;
CI tests minimum/current stable Go, PostgreSQL 16/18, Redis 7.4/8.2 and the pinned
standalone Qdrant server. Optional sqlite-vec checks run CGo-free on Linux, macOS
and Windows. Deployed pgvector operators,
permissions and index limits still determine feature availability.

The [pre-v1 review](pre-v1-review.md) maps the original scope to conformance
tests and persisted fixtures. See the [security policy](../SECURITY.md) for
supported release lines.

## Preparing and publishing

1. Start from latest master. Select an unused version, update VERSION and group
   changes under the matching changelog heading. Keep availability wording honest:
   a prepared release is not yet downloadable as a tag.
2. Review exported API/storage compatibility and upgrade instructions. Run race
   tests, vet, bounded fuzzing, docs/sample smoke checks, release-script tests and
   all backend integration matrices. Review failure/compatibility fixtures and
   vulnerability results. The release workflow repeats the complete CI gate.
3. Merge the reviewed release-preparation PR. Publishing is a separate explicit
   action: dispatch the Release workflow on master with the selected version.
   Before dispatch, check repository tag rulesets, bypass actors and write access
   to determine who can create or move root release tags. Confirm the version is
   unused. The workflow checks VERSION and the changelog, runs full CI including
   the published connector consumer, and fetches master again before creating the
   tag. The checkout, dispatch SHA and current master tip must agree. A retry can
   reuse an existing tag only at the same commit.
4. After publishing, verify the tag/release commit and public Go proxy download,
   and update the quickstart install commands to the published tag. Run
   `python3 scripts/check-docs.py` and `python3 scripts/check-readme-quickstart.py`
   to verify the consumer examples. Announce relevant fixes and
   upgrade steps; follow up on any failed publication rather than retagging.

`Required CI` succeeds only when every verification job succeeds; failures,
cancellations and skipped dependencies fail the gate. Protect master by requiring
this GitHub Actions check, up-to-date branches and pull requests. Keep force pushes
and deletion disabled and apply the protection to administrators. A solo-maintained
repository can require PRs with zero approving reviews; this enforces tested
changes without requiring authors to approve their own PRs. Repository settings
are separate from workflow code and must be verified after configuration.
Redis jobs also have a 30-minute overall limit covering build/startup and samples,
in addition to their individual Go test timeouts.

VERSION identifies the source version for the release workflow. Merging a PR never publishes a new version. Use
`go get github.com/gabisonia/go-vectorstore@latest` for the latest published release
and inspect/pin the resolved version in your application's go.mod.
